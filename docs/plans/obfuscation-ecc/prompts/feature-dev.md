# Задание для feature dev

Выполни `/feature-dev` для номера и файла этапа, переданных в команде запуска. Прочитай файл этапа, `WORKFLOW.md`, исследование в указанных разделах и инструкции реального репозитория. Если номер/файл не передан, запроси только выбор этапа; не выбирай произвольную задачу.

1. Проверь рабочую копию, base, dirty tree и зависимости. Зафиксируй область изменений по правилам WORKFLOW. Не начинай сразу все этапы.
2. Проследи актуальный код компонентов из задания; расхождения с `4cd330d` запиши отдельно. Составь конкретный дизайн, проверяемые предпосылки и план проверок.
3. Выполни этап в его границах. Сохрани контрольный вариант и исследовательские переключатели там, где требуются сравнения. Новое преобразование до измерений остаётся кандидатом.
4. Пройди уместные автоматические и предметные проверки, запиши фактически выполненные команды и результаты. Запланированное не выдавай за выполненное.
5. Сохрани `runs/<NN>/implementation.md`, `state.md`, `checks.json`, при наличии результатов `decision.md`; обнови STATUS. Переведи этап в `REVIEW_REQUIRED`, если разработка и необходимые проверки готовы. При блокировке укажи её причину.

Передай на отдельное Rust review полный diff относительно stage-base, новые файлы, снимок candidate, критерии и журналы. Не объявляй этап COMPLETE по своему внутреннему review. Не запускай следующий этап и не делай commit/push.
