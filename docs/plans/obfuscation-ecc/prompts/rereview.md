# Задание для повторного Rust review

Выполни `/rust-review` указанного этапа заново, используя правила `rust-review.md`. Прочитай все предыдущие отчёты review/fix, stage-base, текущий candidate и критерии этапа.

1. Для каждого прежнего ID независимо проверь причину, исправление и регрессионную проверку. Запиши `CLOSED`, `OPEN` либо `DISMISSED_WITH_EVIDENCE`; последнее требует конкретного подтверждения, а не заявления автора патча.
2. Просмотри весь итоговый diff этапа относительно stage-base и новые файлы. Проверь побочные регрессии, интеграцию и новые дефекты. Review одного fix-патча недостаточно.
3. Проверь актуальность журналов: результаты должны соответствовать текущим исходникам, сборке, профилю и конфигурации. Повтори затронутые проверки; прежние независимые результаты можно использовать только с явным обоснованием применимости.
4. Сохрани новый `review-<round>.md`, не перезаписывая предыдущий. Новый дефект получает новый ID; повторный прежний дефект сохраняет свой ID.

Если остались или появились подтверждённые замечания, выставь `FIX_REQUIRED`: следующий шаг снова `/orch-fix-defect` по шаблону orch-fix.md. Если обязательные проверки недоступны — `BLOCKED`. Только при чистом полном review и выполненной приёмке выставь `COMPLETE`, зафиксируй точный принятый снимок и решение по кандидату. Заверши этот этап; следующий автоматически не начинай.
