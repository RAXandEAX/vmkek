# Задание для Rust review

Выполни `/rust-review` указанного этапа. Прочитай его файл, WORKFLOW, implementation, checks, decision и точный diff относительно stage-base. Проверяй также новые и незакоммиченные файлы; не используй автоматически `HEAD~1` и не захватывай чужой dirty tree. Если снимок не определён, это блокировка проверки.

1. Проверь фактическое выполнение cargo check/fmt/clippy/test для затронутых профилей, затем корректность Rust, unsafe/FFI, границы буферов, переполнение, флаги, ABI и обработку ошибок по применимости. Невыполненный обязательный build gate не означает чистое review.
2. Проверь предметный checklist этапа и связанные изменения Python/shell/manifest. Оцени oracle, изоляцию holdout, статус ошибок, привязку результатов к binary/revision и независимость восстановления.
3. Сопоставь каждое требование с кодом, тестом или артефактом. Не принимай рост байтов/слоёв за стойкость, а solver-proof локального тождества — за корректность всей программы.
4. Для каждого подтверждённого дефекта выдай ID `O<NN>-F<NNN>`, серьёзность, путь/строку, сценарий, последствия и проверяемый критерий исправления. Отличай дефект от необязательного предложения; предложение нового функционала не расширяет этот этап.
5. Сохрани следующий `review-<round>.md`, снимок, покрытие проверки и вердикт. Обнови state и STATUS.

Код не исправляй. При любых открытых подтверждённых замечаниях — `FIX_REQUIRED`. При недоступных обязательных проверках — `BLOCKED`. `COMPLETE` допускается только при отсутствии открытых замечаний, выполненных критериях и записанном экспериментальном решении. Положительный результат стойкости не обязателен для честно завершённого отрицательного эксперимента.
