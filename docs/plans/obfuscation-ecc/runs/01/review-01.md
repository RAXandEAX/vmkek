## Открытые замечания

### O01-F001 HIGH · Ошибка кандидата в transfer обрывает весь receipt

`evaluation/evaluate.py:464`, `:523`. Новый отдельный процесс может завершиться по timeout, с ненулевым статусом, невалидным JSON или ошибкой запуска. В fresh есть обработка, а вызов transfer остаётся без неё. Воспроизведено через `patch.object(evaluate, "score_affine", side_effect=subprocess.TimeoutExpired(["candidate"], 10))` при проходящих baseline и fresh. Исключение ушло из `affine_probe`, файла `affine-hypothesis.json` нет. Остальные seed теряются, опубликованный baseline уже существует.

Критерий закрытия — timeout и ошибка transfer классифицируются в строке, сохраняются донор, target и elapsed, следующие строки выполняются. Тест имитирует сбой одной transfer-ячейки и проверяет статус, сохранение остальных строк и receipt. Некорректный тип JSON результата тоже должен стать `error`, поскольку сейчас `null` приводит к необработанному `TypeError`.

### O01-F002 MEDIUM · Coverage manifest не фиксирует ревизию и собственный генератор

`evaluation/coverage_manifest.py:18–31`. Записанные хэши подтверждают часть файлов, но manifest отсутствует среди них и поле revision отсутствует. Проверено на `coverage-03.json`. Два выпуска из разных Git HEAD с одинаковыми выбранными Python/C файлами и разным кодом протектора имеют одинаковые исходные признаки без baseline. Указанный SHA из `implementation.md` остаётся внешней ручной связкой.

Критерий закрытия — в машиночитаемом manifest фиксировать точный Git HEAD или явную недоступность, версию Python и SHA-256 кода самого генератора. Сохранить существующую привязку переданного baseline и не утверждать, что Git HEAD описывает dirty Python файлы. Тест должен проверять привязку текущего генератора.

## Покрытие этапа

- Реальный результат относится к узкой заранее заданной модели `affine_xor` на ELF. Отдельный фиксированный Python-кандидат сам не вызывает цели, но его текущие права на файловую систему позволяют обратиться к целям. В протоколе этапа недоступность целей кандидату является обязательным условием.
- 4320 ELF ячеек в manifest — план со статусом not_run. PE T4 подтверждает исполнение и SEH. PE recovery, независимые структурный и зависимостный бинарные адаптеры и бюджеты 600/3600 в текущем стенде ещё не выполнены. План допускает явные unsupported/not_run клетки, но требует протокол запуска с тремя бюджетами и конкретные доступные независимые адаптеры. Нельзя присваивать unsupported без конкретного ограничения. Широкая серия по всем адаптерам и PE может оставаться частичной при прозрачной маркировке, если реализована и выполнена поддерживаемая часть протокола.
- Краткие проверки cgroup и нативный T4 дополняют ELF опыт. Пока нет повторяемых runner-fixtures для превышения памяти/тайм-аута/падения/неподдержанного ввода с подтверждением охвата потомков и сохранения результата. Нет сопоставимой серии по отдельным времени сборки, latency функции и памяти всех вариантов.
- Частичный результат стоит сохранить. Для `COMPLETE` нужен отчёт об оставшихся критериях, а после исправлений — новый независимый review. KLEE и Frama-C отсутствуют по имеющимся измерениям.
