# Этап 04 — исследование кодирования региона

Предыдущий арифметический кандидат этапа 03 отклонён. Этот независимый опыт использует ограниченную u64-фикстуру и не зависит от отклонённого генератора. В исходном C выполняются два полезных зависимых действия, `x += b` и `x *= a`. В региональном варианте представление `E(x)=x+k` сохраняется между ними и декодируется после умножения. Все операции используют беззнаковую арифметику modulo 2^64.

Сравниваются plain, немедленная XOR-пара и кодирование региона. Последняя формула учитывает поправку `(1-a)*k`. Прогон компилированных `-O0` функций проверил 625 граничных и 1000 псевдослучайных наборов, независимый Python oracle и контроль неверного декодирования. В fixture нет памяти, кроме исполнения локальных значений, побочных эффектов, переходов или вызовов. Проверка допустимости принимает только декларированные add и multiply_const, мёртвые флаги и scratch без пересечений с операндами, отдельно проверены запреты для памяти, указателей, вызовов, ветвления и floating point. Это проверка данных декларации, а не анализ liveness настоящего IR.

Clang 18.1.3 `-O1 -S -emit-llvm` свёл все три функции к одинаковому телу add/mul/ret. Результат и полный LLVM IR находятся в `/home/rax/.cache/codex-evaluation/ecc-04/normalization-01/`. Хэши исходника, драйвера и результатов записаны в JSON. Результат **REJECT** относится к одному C-примеру и не измеряет native PE/ELF, VM lowering, отдельную стоимость выполнения, восстановление или перенос анализа. Декларируемый эксперимент не интегрирует преобразование в протектор. Невыполненные пункты этапа, включая native-размещение и живые флаги, остаются явно не подтверждены.

`python3 -B -m unittest discover -s evaluation` завершился успешно: 59 тестов. Ошибки в JSON stdout — контролируемые mock-сценарии существующего тестового набора. Лог и SHA указаны в checks.json. Последующие изменения требуют повторной сверки hashes.
