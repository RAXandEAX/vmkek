# Этап 07 — проверка существующих уровней

Профили измерены отдельно. В основной VM `product_program` формирует 258-байтовую программу `LOOKUP + таблица из 256 байтов + RET`; `select` её исполняет. Контроль читает ту же таблицу непосредственно, возвращая отказ на `REJECT`. Новый обычный тест проверяет все 256 значений и повреждённую длину. Имеющийся `ir_level1_and_level2_agree_on_sample_and_l1` сравнивает состояния IR, VM и VM с уровнем 2 на своих фикстурах. Прямое чтение таблицы — модель обхода выбора handler, не модифицированный защищённый PE/ELF.

Для Lab использована настоящая `Layers::add`, включая проверку и authenticated open на каждом вызове. Имеющийся тест `authenticated_word_and_limb_programs_match_a_widened_oracle` сравнивает глубины 3/4 с u128-оракулом для 49 пар и типов U64/I64, проверяя расход fuel 3/6. CODE_BYTES равен 7 для word и 7 для limb. `Layers::memory_bytes()` возвращает 199 байт, `call_memory_bytes()` 82 байта на данном target; это модельные размеры типов, не замер RSS. Проверены существующие ошибки аутентификации в тестах проекта; новых утверждений о произвольных программах здесь нет.

## Результаты

WSL2 x86-64, rustc 1.95.0, release, пять последовательных повторов с фиксированным порядком вариантов, без изоляции CPU. Все результаты — общее время циклов, не задержка защищённой нативной функции. Сырые данные и хэши — `results.json`, полные логи — `native-timing.log`, `lab-timing.log`.

- Основной lookup: 5 400 000 вызовов за повтор, медиана прямого доступа 3 733 002 нс, `select` 19 249 512 нс. Только известные handler tags входят во время; все 256 кодов проверены отдельно. Сумма 220 000 000 во всех вариантах.
- Lab: 20 000 сложений за повтор. Медианы прямого `wrapping_add` 12 209 нс, depth 3 28 509 860 нс, depth 4 56 484 778 нс. Сумма 99 980 000 во всех вариантах. Подготовка двух handles вне цикла заняла 16 227 нс в этом запуске. Отдельные циклы word.open и limb.open дали медианы 25 213 327 и 25 122 805 нс на 20 000 открытий. Это отдельные замеры, их нельзя механически вычитать из общего времени.
- Два release timing теста, тест всех кодов, тест U64/I64 и `cargo clippy --locked --offline -p vmkek -p vmkek-protocol --all-targets -- -D warnings` прошли. `cargo fmt --all -- --check` прошёл. Параметры jobs=4, offline, toolchain и SHA указаны в `results.json`. Результаты timing тестов требуют `--ignored --nocapture`.

## Решение

INCONCLUSIVE для вклада уровней в стойкость. Эти измерения показывают стоимость существующих реализаций на одном хосте и совпадение результата на указанном наборе. Независимое восстановление и transfer, native PE/ELF варианты с отключённым уровнем, startup, отдельная память процесса и размер конечного образа не измерены. Нельзя из фиксированного порядка микробенчмарков выводить точный эффект слоя в приложении.
